# Install or update project skills

Use this skill when an agent receives this repository as the source for setting up another project. The built-in list comes from [`catalog.json`](../../catalog.json); it is a list of **sources**, so Matt Pocock's source, Ponytail, and UI UX Pro Max install packs rather than one skill each. Taste Skill installs its default `design-taste-frontend` variant.

Treat installation, model availability, project initialization, and Git hygiene as one task. Downloading files alone is not completion. Preserve the registered name `agent-skill-setup` when the user refers to this workflow as “agent-skills-setup”.

Matt Pocock's skills are the default project workflow entrypoint: run `setup-matt-pocock-skills` first after installation, then route engineering work to the relevant installed Matt skill. Ponytail complements that workflow with guidance on reuse and minimal complete changes. If Matt's pack is deselected, preserve the project's existing entrypoint. Spec Kit is no longer installed or required; leave any existing project artifacts intact.

1. Resolve the target project root, coding agent (`codex`, `claude-code`, or `cursor`), and whether the request is an installation/repair or an upstream update. Run `python3 scripts/setup.py inspect --project <root> --agent <key>` and read the project's README, existing `AGENTS.md`/`CLAUDE.md`, relevant `docs/`, git remote, existing skill directories, and `.gitignore`. If `.codegraph/` already exists, use CodeGraph to locate code before text search. For a project with application code or released behavior, follow [the established-project path](../../docs/brownfield.md), including its reviewable baseline. Finish when you can name the current documentation layout, pre-existing changes, and which selected items are already present.
2. Show the catalog items as a checkbox list, **all checked by default**, with their current status from `python3 scripts/setup.py list --project <root> --agent <key>`. Ask which boxes to clear only when the user's selection is unknown. A direct request to install all means every catalog item remains selected. Finish when the selected IDs are explicit.
3. Install the Python dependencies from `requirements.txt` into the interpreter environment used for setup. For installation/repair, run `python3 scripts/setup.py install --project <root> --agent <key> --only <comma-separated-ids> --yes --dry-run`, inspect the target paths, then run it without `--dry-run`. For an upstream update, follow [the selected-source update workflow](../../docs/updating.md); rerunning `install` alone does not refresh existing skill content. The script stops on upstream failures; resolve the failure and rerun the affected selection. The installer removes `disable-model-invocation` from each selected skill's `SKILL.md` frontmatter and sets `policy.allow_implicit_invocation: true` in `agents/openai.yaml`, including already-installed members on reruns. Verify both settings and confirm the selected skills appear in the host's skill list; refresh/restart the host if needed. If host-level settings still disable a selected skill, identify and reconcile the exact setting within the requested selection. Automatic eligibility does not mean every skill runs on every task.
4. Initialize **every selected item**, starting with Matt's project setup. Read its guide below, use the project's actual conventions, execute its checks, and record the result. Matt needs tracker/domain/label configuration; Ponytail needs a project guidance link and an invocation check; CodeGraph needs its agent integration and a working index; Archify needs its doctor check and project diagram location; UI UX Pro Max needs its search check and design baseline; Taste Skill needs project-derived design dials. Update runs must recheck these integrations against the new version. Do not label an item initialized because its `SKILL.md` exists.
5. Reconcile project documentation and apply [the exact Git ignore policy](../../docs/git-hygiene.md). Use the existing README/docs convention for one setup entrypoint, preserve existing agent instructions, and link project-specific configuration from the agent instruction file. For an established project, complete the selected CodeGraph/Archify deliverables from [the established-project path](../../docs/brownfield.md); use existing evidence/tools for deselected items rather than installing them implicitly. Keep durable project-specific customization in tracked docs/configuration, not in ignored installed skill files. Document how to reinstall and update the selected sources. Check actual Git behavior and remove only reviewed, previously tracked installation artifacts from the index while retaining local files.

Report each selected source as installed/updated, available to the host/model, initialized, and ignored, with the evidence and relevant paths. List project-specific changes separately from ignored dependency files. If a host restart, missing project preference, or failed check prevents validation, report that item as pending and state the concrete next step; do not declare the full setup complete.

The installer automates commands, not the decisions that depend on the target project's documentation. Read the relevant guide only after the item is selected:

- [Matt Pocock's skills](../../docs/initializers/matt-pocock-skills.md): default workflow entrypoint, issue tracker, triage labels, and domain docs.
- [Ponytail](../../docs/initializers/ponytail.md): reuse and minimal complete changes, with review skills available when needed.
- [CodeGraph](../../docs/initializers/codegraph.md): local agent MCP configuration and index verification.
- [Archify](../../docs/initializers/archify.md): doctor check and diagram location.
- [UI UX Pro Max](../../docs/initializers/ui-ux-pro-max.md): CLI initialization, search check, and existing design system.
- [Taste Skill](../../docs/initializers/taste-skill.md): default variant and project-derived design dials.
