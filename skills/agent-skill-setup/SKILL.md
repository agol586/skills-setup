# Set up a target project

Use this skill when an agent receives this repository as the source for setting up another project. The built-in list comes from [`catalog.json`](../../catalog.json); it is a list of **sources**, so Matt Pocock's source, Ponytail, and UI UX Pro Max install packs rather than one skill each. Taste Skill installs its default `design-taste-frontend` variant.

Matt Pocock's skills are the default project workflow entrypoint: run `setup-matt-pocock-skills` first after installation, then route engineering work to the relevant installed Matt skill. Ponytail complements that workflow with guidance on reuse and minimal complete changes. If Matt's pack is deselected, preserve the project's existing entrypoint. Spec Kit is no longer installed or required; leave any existing project artifacts intact.

1. Resolve the target project root and coding agent (`codex`, `claude-code`, or `cursor`). Run `python3 scripts/setup.py inspect --project <root> --agent <key>` and read the project's README, existing `AGENTS.md`/`CLAUDE.md`, relevant `docs/`, git remote, existing skill directories, and `.gitignore`. If `.codegraph/` already exists, use CodeGraph to locate code before text search. For a project with application code or released behavior, follow [the established-project path](../../docs/brownfield.md), including its reviewable baseline. Finish when you can name the current documentation layout, pre-existing changes, and which selected items are already present.
2. Show the catalog items as a checkbox list, **all checked by default**, with their current status from `python3 scripts/setup.py list --project <root> --agent <key>`. Ask which boxes to clear only when the user's selection is unknown. A direct request to install all means every catalog item remains selected. Finish when the selected IDs are explicit.
3. Install the Python dependencies from `requirements.txt` into the interpreter environment used for setup. Run `python3 scripts/setup.py install --project <root> --agent <key> --only <comma-separated-ids> --yes --dry-run` and inspect the target paths it may modify. Then run the same command without `--dry-run`. The script stops on upstream failures; resolve the failure and rerun selected items. Read the guide for **each selected item** and complete its document-sensitive steps. The installer removes `disable-model-invocation` from each selected skill's `SKILL.md` frontmatter and sets `policy.allow_implicit_invocation: true` in `agents/openai.yaml`, including already-installed members on reruns. Verify both settings and confirm the selected skills appear in the host's skill list; refresh/restart the host if needed. If host-level settings still disable a selected skill, identify the exact setting rather than treating file presence as proof of visibility. Finish when every selected item passes the guide's check, including the prompt-driven Matt setup and invocation-policy check. Automatic eligibility does not mean every skill runs on every task.
4. Reconcile project documentation: use the existing README/docs convention for a single setup entrypoint, record Matt's skills as the default engineering workflow when selected, keep upstream-specific detail in the selected guides or existing project docs, preserve existing agent instructions, and link any new `docs/agents/` configuration from the project's agent instruction file. For an established project, complete the CodeGraph-backed architecture, critical-flow, constraint, and Archify diagram deliverables in [the established-project path](../../docs/brownfield.md) before deriving new agent rules. Keep downloaded skills and their bundled templates, scripts, references, and assets out of Git, together with `skills-lock.json` and local CodeGraph index data. The installer adds ignore rules for the shared `.agents/skills/` directory and the selected agent's skill directory. Ignore any additional upstream scaffolding by its specific generated path, never by ignoring the whole agent directory or all project templates. Record a bootstrap command that restores every selected item. Keep durable project-specific customization in tracked project docs/configuration, not in ignored installed skill files. Commit only project-specific source, configuration, documentation, diagrams, and `.gitignore` changes. For previously tracked installation artifacts, review the exact files and remove only those generated artifacts from the Git index with `git rm --cached`, preserving local copies and project-authored files. Finish when the project docs describe current behavior, what was installed, how to use it, and where its configuration lives; `git status` shows only intended source/config changes.

The installer automates commands, not the decisions that depend on the target project's documentation. Read the relevant guide only after the item is selected:

- [Matt Pocock's skills](../../docs/initializers/matt-pocock-skills.md): default workflow entrypoint, issue tracker, triage labels, and domain docs.
- [Ponytail](../../docs/initializers/ponytail.md): reuse and minimal complete changes, with review skills available when needed.
- [CodeGraph](../../docs/initializers/codegraph.md): local agent MCP configuration and index verification.
- [Archify](../../docs/initializers/archify.md): doctor check and diagram location.
- [UI UX Pro Max](../../docs/initializers/ui-ux-pro-max.md): CLI initialization, search check, and existing design system.
- [Taste Skill](../../docs/initializers/taste-skill.md): default variant and project-derived design dials.
