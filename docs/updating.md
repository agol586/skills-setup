# Update the selected sources

The Python `install` command repairs missing files and invocation policy. It deliberately preserves existing skill content. An upstream update is a separate agent-driven workflow; do not report a repair run as an upgrade, and do not run a global update that touches unselected sources.

1. Resolve the selection and inspect the target as in the main workflow. Read each selected initializer guide. Keep project-specific instructions in the target's existing documentation. Identify local edits inside installed skills so they can be preserved in the backup and reconciled with the new version.
2. For the selected **downloaded skill sources**, create a disposable staging project outside the target and run this repository's `install` command there with the same `--agent` and exact `--only` selection. Exclude CodeGraph from this staging selection: its MCP configuration and index belong to the real project. The fresh stage receives current upstream content, normalized invocation metadata, and tool checks. If staging fails, stop before replacing target files.
3. Compare the actual staged skill names against the target's selected-agent and shared `.agents/skills/` directories. Use `skills-lock.json` source ownership and the initializer's identity checks to distinguish selected dependencies from unrelated same-name skills. Resolve any collision before replacement. Do not copy the staging project's README, agent instructions, `.gitignore`, or other project configuration over the target.
4. Apply [the ignore policy](git-hygiene.md), including `/.skills-setup/backups/`, before creating a uniquely named backup directory there. Verify that the backup path is project-local and ignored. Back up the exact selected directories, their link layout, and the target lock file, and record the restoration mapping. Preserve existing backup runs. Only after a usable backup exists, replace the selected skill directories with the staged contents; replace whole skill directories so stale bundled files do not survive. Keep unselected skills intact.
5. Skills CLI installations may use agent links to shared canonical copies. Copy the resolved staged content into the target's canonical skill directory and retain/recreate only links that resolve within the target. Never leave a link pointing at the disposable staging directory. Merge only the selected skills' entries from the staged lock file into the target lock file, preserving unrelated entries. If replacement or verification fails, restore the affected directories, links, and lock entries from this run's backup before proceeding.
6. Rerun the target's `install` command for the same downloaded-source selection to validate the pack, normalize invocation policy, and run its tool checks. Compare the resulting installed payloads to the stage and account for any intentional project adaptation. Re-run each selected initializer, refresh the host if needed, and verify actual skill availability. Retain the backup until the update is verified; report its path.

When CodeGraph is selected for update, use its documented npm package to refresh the CLI (`npm install -g @colbymchenry/codegraph`), then run this repository's target installation with `--only codegraph --yes`. Follow its initializer to verify the actual project integration and index. Preserve the target's other MCP settings and agent instructions; report CLI/index failures separately from downloaded-skill updates.

Finish with the main workflow's per-source availability, initialization, and Git checks. The stage is disposable only after target verification; an upstream download or version change by itself is not completion.
