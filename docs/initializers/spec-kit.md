# GitHub Spec Kit initializer

Source: [github/spec-kit](https://github.com/github/spec-kit). Official references: [installation](https://github.github.io/spec-kit/installation.html), [existing projects](https://github.github.io/spec-kit/guides/existing-projects.html), and [integrations](https://github.github.io/spec-kit/reference/integrations.html).

The installer provides `specify-cli` through `uv` when needed and runs it through `uv tool run` if the tool executable directory is absent from the current `PATH`. For a project without `.specify/`, it runs `specify init --here --force --non-interactive --ignore-agent-tools --integration <key>`; the existing-project `--force` flag can replace files at Spec Kit managed paths, so inspect the dry run and target diff. If `.specify/` already exists, the installer checks `integration.json` for the selected registration, `speckit.manifest.json` for shared templates/scripts, and the selected integration manifest for skills. It installs a missing integration or upgrades an already registered one to restore missing managed files, then checks registration and both manifests again. If any `speckit-*` skill files remain but `.specify/` is missing, it stops for project-baseline recovery or a reviewed init in an isolated checkout. The agent keys map to `codex`, `claude`, and `cursor-agent` in Spec Kit.

Before writing a constitution, read the project's README, contribution guide, architecture decisions, and CI/test documentation. Add only principles already true or explicitly agreed to. If `.specify/memory/constitution.md` contains substantive rules, preserve and review them; invoke the selected integration's constitution skill for a new project-level constitution (Codex uses `$speckit-constitution`). Do not invent a specification for all existing behavior merely because the tool was installed.

For an established project, finish the [CodeGraph-backed architecture and constraint pass](../brownfield.md) first. Derive the constitution from verified contracts and existing decisions; use the first new specification for one bounded change to the live system.

Check: `specify version` works, the chosen integration's skills/commands exist in the project, `.specify/` is present, and the constitution reflects actual project rules. Review the generated files in `git diff` or `git status` before treating setup as complete.
